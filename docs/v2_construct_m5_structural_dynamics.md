## 2. What this means for the two framed branches

The user's framing said: "If linear is bounded by Din, the problem is graph + input
position. If linear is large and nonlinear small, the problem is dynamics /
normalization." The data:

- **Linear Krylov (`A^k B`)**: bounded at **D_eff ≈ 5.35–5.68 at K=16** under both row-L1
  and gamma-only rescaling. That's **≈ Din (5)**, not the "几十/上百维" the user said
  would point at the dynamics. Removing the normalization (gamma vs row-L1) does
  barely move D_eff (0.05 at K=16). **The normalization is not the bottleneck.**
- **Nonlinear state matrix** (C3's measurement): `D_eff_factor ≈ 1.1·Din`, and
  `M_real ≤ M_A=0` at every (gain, leak) — the recurrent term adds nothing to
  the autocorrelation. The nonlinear collapses onto the same `≈Din`-rank subspace
  the linear Krylov already saturates at.
- The raw substrate (no normalization, rho ≈ 2683): Krylov `D_eff` *drops* from 4.96
  at K=1 to **1.02 at K=16**. That's tanh saturation, the v1 finding.

So the two branches land on **neither hypothesis as the sole cause**:
- Hypothesis 1 (graph lacks recurrence): rejected.
- Hypothesis 2 (normalization suppresses cycles): rejected — gamma-only is ≈ identical
  to row-L1 at the substrate level, and both suppress only to `≈Din` rather than to 1.

The data shows the recurrent expansion's effective rank is bounded by **`≈ Din` on
this substrate, with this input geometry, for any preprocessing that keeps tanh in its
linear regime**. The bound is **`span(B) ≈ Din`** for the ORN-aligned W_in — the input
projects onto `Din=5` channels, and `A^k · B ⊂ span(A^k) · span(B)` saturates at the
same direction set `span(B)` because the cycles on this dense homogeneous induced
block don't carry independent information beyond the input shape.

## 3. The third branch the data opens

What this implies is a **constructional question about the INPUT GEOMETRY and the
SUBSTRATE'S EIGENSTRUCTURE**, not about the existence of cycles:

- (a) **Spread the input beyond the ORN rows.** The current W_in support is exactly the
  ORN population (243 nodes) and the input dimension is 5. Adding PN or KC rows to
  the support would increase `span(B)`, but only if those rows carry independent
  signal directions.
- (b) **Use a substrate whose eigenstructure carries independent directions.** The
  C2 expansion is dense and uniform (mean out-degree 80 on a 1000-node induced
  block with the typed population drawn from one ORN-seeded frontier). Such a substrate
  has a few dominant eigenmodes and a long tail of similar-magnitude modes — the
  `span(A)` saturates quickly. A sparser subgraph, or a different seed set, could
  have a richer spectral distribution.
- (c) **Don't claim reservoir; treat as a sensory feature transformer.** The
  user named this route: a fixed connectome-constrained kernel that propagates X → H
  → readout, without the memory / state-spread properties a reservoir needs.

The C3 gate's failure is then not "the substrate can't be a reservoir" in the binary
sense; it's **"with this substrate and this input geometry, the recurrent expansion
collapses onto `≈Din` and the nonlinear dynamics can't recover more than that."**

## 4. What is NOT claimed

- **That the cycles are "wrong" cycles** that "don't contribute" — the substrate's
  cycle_edges = 1.0 says every edge lies on some cycle, and ORN-reachable nodes are
  100 % in the recurrent core.
- **That the row-L1 normalization is the bottleneck** — gamma-only rescaling, which
  avoids row normalization, gives essentially the same D_eff curve.
- **That v3-A (raw + global γ) would fix C3 by itself.** D_eff moves from 5.35
  (row-L1) to 5.68 (gamma-only), a 6 % improvement. Both saturate the Krylov at
  `≈Din`. The linear reachability bound is not the binding constraint — the input
  geometry is.
- **That v3 redesign is the next step.** M5 says the data does not pick one of the
  user's two branches as the cause. The next step is for the owner to choose among
  (a) input-geometry, (b) substrate-eigenstructure, or (c) drop the reservoir claim
  — and that is an owner decision, not a code change to the construct check.
